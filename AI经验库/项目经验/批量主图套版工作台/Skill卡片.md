# 批量主图套版工作台 - Skill 卡片

## 可复用 Skill

### 归档或接手电商主图自动套版项目

适用场景：需要恢复、评估或继续开发「电商主图自动套版 / 批量主图套版工作台」。

执行步骤：
1. 先读 `项目状态.md`，确认源码仓库、运行方式和当前风险。
2. 打开源码仓库 <https://github.com/wang-zefeng/batch-main-image> 或本地工作区 `C:\Users\Administrator\Documents\设计自动化`。
3. 读 `README.md`，确认 MVP 目标是「活动线框 + 产品资料 + 机制数据 -> 主图 PNG」。
4. 读 `data/product-lineframe-template.json` 和 `docs/product-wireframe-template.md`，先理解字段和槽位，再改 UI。
5. 读 `src/app.js` 的关键路径：`parseCsv`、`briefFromCsvRow`、`runPreflight`、`render`、`exportPng`、`exportBatchPng`。
6. 本地验证时直接浏览器打开 `index.html`，不需要安装依赖或构建。
7. 做功能时保持小闭环：输入 CSV / 图片素材 -> 映射为 `brief` -> 预检 -> Canvas 预览 -> PNG 输出。

项目边界：
- 不优先做用户系统、支付系统、复杂权限、自动爬图或复杂 PSD 还原。
- 不让 AI 直接生成最终主图；AI 只生成结构化卖点、机制文案或字段建议。
- 不在经验库上传完整源码、大素材、导出视频/图片、日志、`.env`、`.git`、`node_modules`。

建议验证清单：
- `index.html` 能打开。
- CSV 示例能应用。
- 产品图文件名能匹配本地素材。
- 预检能识别缺字段、缺图片、错误模板 ID。
- 单张 PNG 导出可用。
- 批量 PNG 导出路径可用。

### 2026-11-13：5217 上传 PSD 的商品主体自动适配最小规则

适用范围：Windows 本地 5217 Layer Studio，用户上传并已绑定商品图槽位的 PSD。以下针对现有分层编辑器，不沿用上面早期静态 index.html 的运行入口。

长期约束：Excel 负责内容，模板负责布局，组件负责特殊视觉元素。任意已绑定上传母版都可使用；V0.2 仅为普通可选模板。真实图片按商品 ID 匹配，不把商品 ID 当店铺 SKU，不生成新包装图。未绑定文字、背景、Logo 和装饰原样保留；赠品仅更新已有组件的绑定内容，空值遵循原组件规则，不继承上一商品、不创建新组件。

输入：母版原商品图槽位及其可编辑展示区域、真实产品 PNG、当前 Excel 内容。输出：保留源图像字节的等比放置位置与尺寸、独立可编辑设计和实际 PNG。

执行规则：
1. 以该模板保存的商品展示区域为边界；不写死模板 ID、画布大小或产品文件名。先检查主体是否已经用满槽位；若必须扩大区域才能明显放大，明确说明空间限制并取得用户同意，只调整商品区域，不擅自移动其他层。
2. 通过 Alpha 非透明像素计算完整主体边界，忽略外部透明留白。保留全部非透明像素，包含泵头、包装、Logo、小配件与低透明度阴影；不得裁切包装来制造“填满”效果。
3. 默认在槽位短边的 2.5% 处留安全边距。统一使用一个缩放系数，完整约束在安全区内；不用横纵独立拉伸或 cover 裁切。
4. 细长轮廓（宽高比小于 0.5）优先利用可用高度。较宽组合在完整容纳的前提下，以有效 Alpha 面积控制体量：缩放不超过 sqrt(安全区面积 × 0.66 / 源有效面积)。这是一种形态近似，不是瓶数识别或语义分割，不宣称所有包装都可自动准确分类。
5. 默认水平、垂直居中。用 Alpha 平方加权求重心，减少淡阴影干扰；对几何中心与重心的差做半幅补偿，每轴不超过安全区尺寸的 4%，最终再约束到安全区。相同模板优先协调视觉体量，不要求每款等宽、等高。
6. 当前槽位尺寸决定可用空间，不让历史 referenceHeight 继续限制新商品。扩大槽位后若仍用原商品高度作上限，图片会持续偏小。缓存图片也须在主体测量前重新确保解码完成，避免连续预览后尺寸漂移。
7. 以实际画布和 PNG 做视觉验收。保留修复前结果，并排查看同一模板下不同产品；几何检查通过不等于商业视觉已被用户认可。新模板仍须人工确认槽位与相邻文案的关系。

验证闭环：
- 原表中仅勾选指定 4 款，走现有预览、生成、保存、PNG 与 ZIP 导出流程，不生成全部商品。
- 核对源图片 SHA256、主体宽高比、安全边界及小配件完整性；补测真实单瓶和其他长宽比槽位。
- 逐图比对预览、画布、PNG、ZIP；对比旧设计确认只有产品位置和尺寸发生变化，营销文字、固定图层、绑定、Excel 和图库不变。
- 回归组件分组、样式、整体变换和空字段规则；旧生成项目保持独立，不回写历史设计。
- 实现位置：src/render.js 的 silhouette / fitProduct；验证：tests/product-fit.mjs、tests/product-provider.mjs、tests/identifiers.mjs、tests/component-batch.mjs、tests/components.mjs，及 npm run build、JS 语法检查、git diff --check。

已验证：用户上传的红色 PSD 中，获准只向上扩展商品区域后，原 4 款主体高度由 332 px 增至约 391–458 px；双瓶、三瓶与补充装组合的有效视觉面积更接近。预览、画布及导出一致；另测真实单瓶与带小配件的边界夹具。没有修改原产品像素、文案、绑定或赠品组件。商业效果最终仍由用户验收。

限制：不透明白底图无法仅靠 Alpha 判断商品轮廓，按完整图片安全容纳，不自动抠图。宽松阴影、复杂异形、极端横向套装及全新模板仍需人工检查；上述阈值是当前最小默认值，不是所有商业设计的通用最优值。业务 PSD、图片、数据库、实际截图与原始日志只留本机，不上传经验库。
