# 批量主图套版工作台 - 经验卡片

## 项目经验

### 主图套版 MVP 先拆数据层，不先追求最终设计自动化

结论：第一版应验证「活动线框 + 产品资料 + 机制数据 -> 主图 PNG」的闭环，而不是让 AI 或复杂设计系统直接生成最终主图。

可复用做法：
- 把主图拆成背景层、产品层、机制层、文案层、线框层。
- 用结构化 `brief` 管理产品、活动、文案、赠品、右侧内容槽和模板 ID。
- 用模板 JSON 管理槽位、尺寸、顺序和字段绑定。
- CSV / Excel 只负责输入产品和活动机制，渲染逻辑负责把字段放到固定槽位。
- 产品图和赠品图先用本地文件名精确匹配，避免第一版引入脆弱爬虫。
- 导出前必须预检缺字段、缺图片、模板 ID 和文案长度。

已验证事实：
- 当前源码是无依赖静态 MVP，可直接打开 `index.html`。
- `src/app.js` 已包含 CSV 解析、批量行映射、产品素材文件名匹配、预检、Canvas 渲染和 PNG 导出。
- `data/product-lineframe-template.json` 已把双11预售固定分层模板拆成可解释字段和槽位。

坑点：
- 不要把完整源码、`.git`、素材、导出图片或日志直接塞进经验库；经验库只存状态、链接、索引和可复用结论。
- 本地工作区没有 git remote，源码仓库链接要用用户确认的 <https://github.com/wang-zefeng/batch-main-image>。
- AI 后续只适合生成可审核的结构化卖点/机制字段，不适合绕过人工检查直接出最终主图。

### 分层 PSD 导入的视觉回归

- 保留 PSD 原字节、逐层素材和独立合成预览。对未改字的文字层使用 PSD 自带像素，改字后按保存的文字属性渲染。
- 用同一渲染器生成编辑画布和 PNG。分别比较原稿与导入画布、编辑画布与解码后的 PNG，并验证刷新后槽位和替换图仍在。
- 一个旧版样式 PSD 的 lfx2 效果有 enab 却缺少 present。psd-tools 1.24 会跳过这些效果。仅在内存副本中为此类描述补上 present，再按层栅格化；保留原 PSD 字节。该样本中最大通道偏差超过 8 的像素从 44,784 降到 1,330（512 × 512）。
- 商品测试样稿的零像素差异只覆盖该样稿；新业务模板仍需检查字体、剪贴层和复杂效果。

### PSD 文字兼容与母版隔离

- 即使文字图层按位图渲染，也要保留 PSD 原文、样式分段和字体。用户转换后先显示原缓存，改字或换字体时在同一图层切换到文字渲染。旧草稿可用保存的原始 PSD 补回文字字段。
- 同时验收三件事：源合成图与导入图的通道误差、改字后原文字边界外的变化像素、下载 PNG 与编辑画布是否一致。整体均值较低也可能掩盖局部颜色错误，需要并排看图。
- 生成设计时分配独立作品 ID，保留母版 ID 和槽位 ID。修改后比较母版完整记录与修订号，并在真实服务重启后用干净浏览器验证恢复。

### Excel 商品裂变的导出验收

- 生成时将 SKU、稳定槽位 ID、母版修订与独立设计 ID 关联，逐行记录成功或失败。用一个缺图行验证失败隔离，再补素材只重试该行。
- 批量 ZIP 导出时重新读取每个已保存设计。验收时单独改第二张图，再逐一对比 ZIP 内 PNG 与单张编辑器画布，避免导出旧预览。
- 独立读取 PNG，以包装实色像素测量实际边界并对照理论等比尺寸；对三个结果的非变量区域逐像素比较。服务重启后使用空浏览器会话重新导出并比较散列。

### 裂变功能的首次体验

- 空的母版选择、文件上传和字段映射不足以解释流程。提供独立练习入口，自动准备虚构商品和图片，用“母版固定版式 + 每行替换内容 = 每行一张独立设计”组织四步操作。
- 示例必须走真实保存、映射、生成与导出接口；允许直接改商品表，并排预览。不要展示预制结果冒充生成。
- 生成后单张修改不会回写商品表；下载应读取最新设计。测试同时验证源母版未变、单行重生成不影响其他行、干净浏览器恢复。
- 页面步骤导航若用锚点，不能覆盖存放批次 ID 的 URL hash。使用 scrollIntoView 保留恢复地址。
